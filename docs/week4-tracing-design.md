## Existing boundary and smallest adapter

`evaluation/provider.py:configuration_check()` rejects custom provider origins and enabled `LANGCHAIN_TRACING_V2`/`LANGSMITH_TRACING`. `MeteredOpenAI` uses the official origin, no environment proxy, redirects or SDK retries; strict schemas, redaction, byte envelopes, usage settlement and journaling remain valuable patterns. Historical dispatchers bind excluded private history and old approvals. Do not invoke them, patch their checks, set hidden tracing around them or fabricate ledger bindings.

Propose a separate `evaluation/week4/` adapter with a new entry point, fresh project ledger and independently reviewed authorization contract. It imports inherited `graph.workflow.build_workflow`, `graph.state.initialize_state`, and the five actual agents' `create_agent(llm=...)` factories. Inject an independently metered StructuredLLM-compatible provider and pass those real factories through the graph's existing `agents=` seam. Use `max_retries=0` in initial state, in-memory/no persistent checkpoint for the first benchmark and no external evidence or validation tool configuration. The actual graph still decides routes, holds and report policy. Do not replace agent reasoning with a benchmark shortcut. The inherited validator attempts a model review even without a tool and then enforces NOT_TESTED. Record its actual model attempt if reached; do not manufacture a tool child.

New provider implements the existing `with_structured_output(...).invoke(messages)` interface and preserves applicable wire-schema, handle, redaction, usage and serialized-envelope contracts from `evaluation/provider.py`, without constructing its guard-protected dispatcher. Reuse side-effect-free helpers only after inspection. It obtains actual raw provider usage while returning the parsed schema expected by `agents/common.py:ask()`. The fresh adapter explicitly permits only its own bounded/redacted tracing path and must undergo security review and parity checks before authorization; a separate module is not itself permission to remove any safety property. Automatic SDK environment tracing remains off to avoid raw prompt leakage and duplicate runs. A scoped explicit LangSmith client transports only approved redacted projections. No monkey patching inherited globals or safety checks.

## Run tree and receipts

One exported root per `(dataset_version, case_id, arm, repetition)` invocation, named `week4.case`. Metadata includes input hash, experiment/arm ID, source/config/prompt/schema/adapter hashes, model requested/resolved, transport mode, stage applicability, terminal status, timestamps and error class. Link root UUID locally and remotely to the case ID; never use only positional order. A rerun gets a fresh repetition/root, not replacement history. For a 40-case single-pass arm require 40 distinct verified roots; baseline and final therefore each need their own 40 roots.

Root children are actual graph/node spans, with model grandchildren for every actual network model call. Actual evidence collectors or validation tools, if later configured and authorized, receive tool children with real starts/results/errors. Local evidence catalog/grounding operations can be child spans tagged deterministic; they are not external tool calls. No invented skipped-stage, model or tool runs. A hold may have only early-node children; show expected versus observed counts and absence of later stages. Require at least the actual executed model children and any actual tool children, never an empty decorative root claiming full execution.

Use explicit parent context around the real injected provider/tool boundaries; verify context propagates across sync/async graph execution. Capture monotonic durations and wall timestamps, actual request index, bounded schema/model options, parsed/redacted output, safe errors and usage metadata before `ask()` collapses exceptions. Root totals must reconcile to actual child receipts and local journal, including failed attempts. Avoid double instrumentation of the same call. Keep redacted projections useful enough for review but disallow raw headers, secrets, private URLs, credentials, driver/provider exception bodies and unfiltered inputs/outputs. Evidence snapshot hashes and canonical IDs must correspond to the sanitized inference view.

Expected answers, labels, rubric, family catalog and human review live only in a separate evaluator process/read boundary after inference artifacts close. Inference loader reads an explicit allowlist; it cannot accept a labeled row or arbitrary metadata as prompt content. Domain `expected_behavior` may describe the user's API requirement; it must not smuggle evaluator causal answers. Review for text leakage as well as forbidden keys. Traces of inference exclude evaluator labels; post-inference evaluation links scores by root ID without injecting expected answers into runtime state.

Unknown usage is null, keeps the full pre-call reservation, invalidates complete priced-cost reporting and stops additional provider dispatch when bounded accounting cannot be established. Never estimate tokens as provider receipts. Record known usage even when parsing fails. Missing/oversized usage, inconsistent child totals, redaction failure or broken context halt the batch. Export failure records `TRACE_EXPORT_FAILED`, retains restricted local sanitized journal and actual costs, and marks tracing incomplete; it does not erase quality errors or trigger a second paid inference. Future trace-only retransmission must be idempotent on root/child IDs and explicitly reconciled. Assignment trace completeness is not satisfied until remote root and children can be retrieved and matched to local IDs, timestamps/status and usage. A successful SDK send alone is insufficient.
