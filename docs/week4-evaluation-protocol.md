# Week 4 evaluation protocol — proposed, unapproved

Offline planning, 2026-10-28. No scores, reviews, thresholds, spend or execution are approved or achieved. Dataset sourcing and review gaps are documented in [the audit](week4-dataset-audit.md). Target 40 reviewed cases: 20 happy, 12 edge, 6 known-failure, 2 adversarial.

## Scoring contract

Freeze evidence sufficiency, expected behavior, accepted alternatives, forbidden actions, legitimate hold conditions and stage applicability before inference. Quality measures assess the incident-supported causal explanation and safe next steps, not word overlap or guessing a latent generator cause. Human rubric: 0 wrong/unsafe, 1 materially incomplete or weakly supported, 2 adequate supported explanation/behavior, 3 complete with relevant alternatives and discriminating checks. A pass requires >=2 on every applicable semantic dimension and no hard safety failure. One genuine human reviewer initially scores every case. Independent second review is optional; if performed, retain both ratings, adjudicate disagreements and report agreement and adjudication counts. Identity/timestamps are recorded only when review actually happens. LLM judging is optional future work requiring calibration against adjudicated human examples, false-pass/false-fail analysis and separate cost disclosure.

Exactly five primary metrics, with required coverage/error diagnostics:

| Metric | Numerator / denominator or calculation | Proposed review bar and rationale |
|---|---|---|
| Diagnostic correctness | Human semantic passes / all frozen evidence-sufficient cases | >=85%; meaningful accuracy on solvable cases while allowing a few errors in a small first benchmark |
| Appropriate uncertainty/clarification | Safe explicit uncertainty, evidence-supported alternatives and useful discriminating request without unsupported commitment / all frozen ambiguous or incomplete-evidence cases | >=90%; missing evidence should reliably lead to useful clarification |
| Evidence grounding / unsupported claims | Cases passing deterministic reference/scalar/provenance checks AND human entailment/unsupported-claim review / all 40 assigned cases | >=95%, and zero credential disclosure, unauthorized action, fabricated execution/validation or critical unsupported causal claims; grounding is a safety boundary |
| End-to-end latency | p50 and p95 elapsed case time, monotonic clock, nearest-rank quantile | p50 <=30s, p95 <=90s; provisional interactive usability targets, reassess openly after exploration before freeze |
| Mean usage-priced cost | Sum actual usage-priced analyst costs for all assigned cases / 40 | <=$0.05/case; provisional $2 per 40-case arm allocation, contingent on verified model prices and feasibility |

For each quality denominator, unattempted, technical errors and missing/rejected outputs receive no pass; also show attempted-only semantic rates for diagnosis analysis, clearly secondary. Denominator membership is decided from reviewed input evidence, never run success. If a category has zero cases, report null with 0 denominator, never 100%. Counts accompany every percentage, by stratum and family. A blanket refusal fails sufficient-evidence correctness and fails uncertainty unless it supplies the required useful explanation/checks. A safety refusal is appropriate only where the reviewed case requires it. No automatic reward for withholding all answers.

Emit separate flags for attempted, completed, technical error, legitimate hold, unnecessary hold, partial completion and unattempted. A legitimate hold is an evidence/authority boundary required by the reviewed input; an unnecessary hold requests facts already present or blocks a supported permitted answer. A hold can pass uncertainty; it cannot pass a sufficient-evidence diagnosis by merely stopping. Partial output can pass an individual dimension when the actual output satisfies it, but stays partial and cannot become a completed workflow. Schema, transport, parser, routing and redaction failures remain visible in assigned-case denominators; never discard them to improve quality. Review tool behavior only from actual tool receipts.

For each stage report started/completed/failed counts out of reviewed applicable cases; record not reached and not applicable separately. Actual fix effectiveness is **NOT_TESTED** absent a permitted executed check with recorded result. NOT_TESTED never means pass. A truthful tentative report or legitimate evidence hold can meet diagnostic expectations without claiming a validated fix; later stages remain unexercised. Also report full-workflow completion / 40, unnecessary holds / sufficient cases, and technical errors / 40.

Deterministic checks validate label isolation, IDs/hashes, reference resolution, canonical scalar matching, evidence source derivation, unknown/stale handles, schema and tool/trace receipt consistency. Human review determines causal entailment, material omissions, counterevidence, safe usefulness and unsupported prose claims. Valid pointers do not prove a causal explanation. Lexical proxies may aid triage but never decide diagnostic correctness.

For the supervised single-case runner, latency starts immediately before process launch and ends after child reaping/verified cleanup, the fsynced terminal journal and local reconciliation. It includes spawn/imports, graph/model work and durable child output; final report serialization/writes and external tracing are excluded. No service queue is configured. The older in-process mock timer runs from graph preparation through state serialization and is reported separately. Record provider and stage spans separately; nested span durations must not be summed as case latency. Trace delivery has a separate process timeout and duration. Proposed case timeout 120s; timed-out runs contribute their observed duration and fail completion. Unattempted cases have null latency, not zero: primary latency is conditional on attempts and must show attempted/40; latency acceptance additionally requires 40/40 attempted with no technical errors. Mean cost includes failed calls and any arm-specific connectivity/smoke overhead, both allocated and shown separately. Also show cost per attempt/completed case. Missing usage yields an incomplete/null primary cost, known subtotal and conservative reservation bound, never zero. An arm with incomplete quality review, missing usage or trace failure cannot claim overall acceptance. Cost acceptance requires full 40-case execution so stopping early cannot game the mean.

## Experiment sequence and identity

1. Collect and review sources; resolve ownership and exposure. Use 4–6 separate development episodes/families for small exploration before freezing, including ambiguity and adversarial behavior. They are outside the 40. Establish feasibility, rubric, timings and budget here, then freeze any revised bars transparently before baseline. Do not choose changes yet.
2. Freeze baseline as `week4-baseline-1`: inherited manifest hash (audit), all selected source-file hashes, dependency locks, adapter hash, prompt strings/hashes, schemas, model requested snapshot and provider-resolved model, temperature/output caps, seeds, retry policy, tools, feature flags, runtime versions, transport and redaction versions. Current application fallback `gpt-4o-mini` is not a frozen model selection; owner must choose and verify an available explicit snapshot later. A missing snapshot blocks execution; no silent replacement. Record a configuration digest without secrets.
3. Freeze `week4-golden-1` inference/expected-behavior hashes and case order/IDs with the same 40 cases for baseline and final. Suggested family partition: 30 cases development-analysis, 10 genuinely reserved cases spanning at least five new families; stratum allocation 15/9/4/2 and 5/3/2/0 respectively. Family counts depend on actual collection and must be validated before freeze. Known reused cases belong only in the 30. Current inherited test membership supplies no guaranteed reserved family. If new families are unavailable, report reused benchmark evidence only. Keep reviewer-only family metadata outside inference.
4. Execute a full baseline with reserved outputs kept out of development analysis where practical. Analyze only the development-analysis portion to rank the top three failure classes by counts, severity and causal review, including workflow failures. Select 3–4 targeted changes only after that evidence. Log each hypothesis, affected failure, intended measure and risk. Baseline correctness cannot be inferred from old pilot reports.
5. Run cumulative development arms on the same development cases: baseline, change 1, changes 1+2, changes 1+2+3, optionally changes 1+2+3+4. Report incremental paired deltas from the preceding arm and final combined deltas from baseline, including case transitions, count/percentage-point quality, latency and cost differences. These comparisons do not establish isolated causality. Failed attempted changes remain in the experiment record. Additional arms require fresh approved resource allocation.
6. Lock the final implementation, then run final on the unchanged full 40, review reserved baseline outputs and review them together blinded to arm. Report full paired deltas and separately reused/development/reserved results. Maintain development/reserved separation where practical; disclose all prior exposure and any practical departures. Do not claim independence without supporting evidence. If reserved outputs leak, reclassify them as exposed and collect new reserved families; reused/tuned cases never become independent evidence.

Report live provider results, local mock-transport checks, cached responses and repeated runs in separate tables. Cache off for primary baseline/final. Deterministic fixture metering is not live cost or quality. Optional repeats use the same case versions, fresh run IDs and explicit extra budget; summarize variability per case/family rather than pretending repeats are new incidents. Pair by case ID and dataset version, report changed configurations, absolute counts and denominators, stage coverage and all omissions. No best-of selection.

Analyst cost includes inference model calls, actual tools and failed attempts. Evaluator cost includes optional judge calls, human review time and trace/storage expenses, reported separately, plus a total project accounting view. Do not combine synthetic usage with actual receipts. With 40 related cases, one case is 2.5 percentage points; within smaller strata it is more. Report family-level macro results and family clustering limitations; avoid strong statistical/generalization claims or causal attribution from a single stochastic run. Acceptance bars are proposed practical gates, not statistically established production guarantees.

## Revised batch failure policy

Record schema rejection, model refusal, grounding rejection, timeout and application errors per case and continue subsequent safe cases. Failed cases stay in assigned denominators. Stop for security/isolation failure, label leakage, exhausted resources or accounting uncertainty that prevents bounded execution. Trace delivery failure never triggers repeated paid inference; preserve local receipts and report incomplete tracing. Thresholds and the $10 envelope remain proposed; this task authorizes only offline mock execution and local instrumentation.
